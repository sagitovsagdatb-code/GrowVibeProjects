# PRD: «Трёхдневный Сплит» — мини-приложение для тренировок в зале

**Версия документа:** 1.0
**Дата:** 16 сентября 2026
**Автор запроса:** Sagdat
**Статус:** Готов к разработке (MVP уже реализован как прототип, см. раздел 11)

---

## 1. Проблема

Пользователь тренируется в зале самостоятельно, без тренера. Программа тренировок (сплит на 3 дня) сейчас хранится в разрозненном виде: скриншоты переписки в мессенджере и отдельная таблица (Google Sheets / Excel-скриншот). Из-за этого:

- Перед подходом приходится листать чаты и скриншоты, чтобы вспомнить рабочий вес и число повторений.
- Нет визуального ориентира, какое именно упражнение имеется в виду по названию.
- Нет способа быстро отметить, что уже сделано за тренировку.
- Программой неудобно делиться с другими — она размазана по разным источникам.

## 2. Цель продукта

Дать пользователю (и его товарищам по залу) единое лёгкое мини-приложение, открываемое по ссылке с телефона, которое:

1. Хранит программу тренировок, структурированную по трём дням сплита.
2. Показывает вес / повторения / отдых по каждому подходу в удобной табличной форме.
3. Помогает мгновенно узнавать упражнение по картинке-иконке.
4. Позволяет отмечать прогресс прямо во время тренировки.
5. Может быть переслано другим людям в зале без дополнительной настройки.

## 3. Целевая аудитория

- **Основной пользователь:** сам автор программы — тренируется без тренера, ведёт учёт весов вручную.
- **Вторичная аудитория:** его товарищи по залу, которым можно переслать ссылку и которые будут пользоваться тем же или скопированным приложением как референсом/шаблоном.

Технический уровень аудитории — обычный пользователь смартфона, никаких профессиональных навыков не требуется.

## 4. Формат продукта

**Мини-приложение** (не нативное приложение, не файл для скачивания): одностраничный веб-инструмент, открывается по ссылке в браузере телефона или компьютера, без установки и регистрации.

## 5. Объём (Scope)

### 5.1 Входит в MVP

- Главный экран со списком тренировочных дней (карточки).
- Экран дня тренировки со списком упражнений.
- Для каждого упражнения: иконка-пиктограмма, название, таблица подходов (вес / повторы / отдых).
- Группировка упражнений в суперсеты (блоки A / Б / В), где это соответствует реальной программе.
- Отметка выполнения упражнения (чекбокс) и индикатор прогресса по дню (X из Y).
- Кнопка сброса отметок за тренировку.
- Дружелюбный, спортивный визуальный стиль; подходит для использования на телефоне.
- Поддержка светлой и тёмной темы устройства.
- Возможность поделиться ссылкой на приложение с другими людьми.

### 5.2 Не входит в MVP (Out of scope)

- Регистрация пользователей, аккаунты, авторизация.
- Синхронизация прогресса между устройствами/пользователями.
- Редактирование программы тренировок через интерфейс (сейчас правки вносятся в код/данные).
- Таймер отдыха с обратным отсчётом и звуковым сигналом.
- История тренировок по датам / графики прогресса весов во времени.
- Реальные фото/видео упражнений (используются схематичные иконки).
- Push-уведомления, напоминания о тренировке.
- Интеграция с фитнес-трекерами / сторонними сервисами.

Эти пункты — кандидаты для следующих итераций (см. раздел 10).

## 6. Пользовательские сценарии

1. **Пользователь приходит в зал в понедельник.** Открывает ссылку на телефоне → видит главный экран → нажимает карточку «Ноги» → видит все упражнения дня с весами и отдыхом → выполняет подход → отмечает упражнение галочкой → к концу тренировки видит прогресс 6 из 6 и поздравительный баннер.
2. **Пользователь не помнит, что такое «тяга горизонтального блока».** Смотрит на иконку рядом с названием и сразу понимает, какое это движение и каким снарядом/тренажёром оно выполняется.
3. **Пользователь хочет тренироваться на неделе ещё раз в тот же день.** Нажимает «Сбросить отметки за сегодня», чекбоксы очищаются, таблицы весов остаются.
4. **Пользователь делится программой с другом по залу.** Копирует ссылку на приложение и отправляет её — друг открывает приложение без установки и регистрации.

| № | Требование | Приоритет |

| F2 | Переход на экран дня по нажатию на карточку | Must |
| F3 | Экран дня показывает упражнения, сгруппированные по суперсетам (где применимо) | Must |
| F4 | У каждого упражнения — иконка, название, таблица подходов (номер / вес / повторы / отдых) | Must |

| F6 | Индикатор прогресса (прогресс-бар + счётчик «сделано/всего») по дню | Must |

## 8. Модель данных

Программа хранится как статичная структура (объект в коде приложения), без бэкенда:

```
День {
  id: string                // "legs" | "back" | "chest"
  title: string              // "Ноги"
  num: string                 // "День 01"
  sub: string                  // "Понедельник"
  accent: цвет-токен
  superset[]:
    Superset {
      label: string           // "A" | "Б" | "В" | ""
      hint: string
      exercise[]:
        Exercise {
          name: string
          icon: string          // ключ иконки-пиктограммы
          note?: string          // доп. пояснение по технике
          sets[]:
            Set { n: number, w: string, r: string, rest: string }
        }
    }
}
```

Прогресс пользователя хранится в `localStorage` браузера в виде:

```json
{ "legs": { "0-0-0": true, "0-0-1": false, ... }, "back": {...}, "chest": {...} }
```

где ключ — `дата-структуры "supersetIndex-exerciseIndex"`. Это сознательно локальное, посетительское хранилище: прогресс не покидает браузер конкретного человека и не виден Клоду или другим пользователям.

## 9. Нефункциональные требования

- **Производительность:** мгновенная загрузка, без внешних API-запросов, весь код в одном HTML-файле.
- **Офлайн:** после первой загрузки страница работает без сети (все стили/скрипты инлайн, шрифты — единственная внешняя зависимость через Google Fonts).
- **Доступность:** чекбоксы доступны с клавиатуры (role="checkbox", обработка Enter/Space), видимый фокус.
- **Приватность:** никаких персональных данных не передаётся на сервер; прогресс — только в браузере пользователя.
- **Совместимость:** современные мобильные и десктопные браузеры (Chrome, Safari, Edge, Firefox).

## 10. Технический подход / архитектура

- **Стек:** чистый HTML + CSS + vanilla JavaScript, без фреймворков и сборки. Один самодостаточный файл.
- **Хостинг:** публикуется как веб-страница по приватной ссылке (Claude Artifacts); при необходимости может быть перенесён на любой статический хостинг (GitHub Pages, Vercel, Netlify) без изменений в коде.
- **Иконки:** инлайновые SVG-пиктограммы, нарисованные вручную под каждое упражнение — не требуют внешних изображений или загрузки файлов.
- **Хранение состояния:** `localStorage`, без бэкенда и базы данных.
- **Расширение программы:** новые дни/упражнения добавляются редактированием JS-объекта `DAYS` — не требует навыков фронтенд-разработки выше базовых.

### Кандидаты для следующей итерации (если потребуется бэкенд)

- Синхронизация между устройствами → потребует лёгкий бэкенд (например, Supabase/Firebase) и авторизацию.
- Совместное использование программы командой с общим прогрессом → потребует серверное хранилище вместо `localStorage`.
- Таймер отдыха → чисто клиентская доработка, бэкенд не нужен.
- Редактирование программы через UI (админка) → форма + сохранение в `localStorage` или бэкенд.

## 11. Текущий статус

Прототип, реализующий весь MVP (разделы 5.1, 7), уже собран и опубликован как рабочее мини-приложение. Данные по упражнениям (веса, подходы, повторы, отдых) перенесены из реальных тренировок пользователя, а не являются шаблоном. Документ фиксирует требования постфактум — как техническое задание для дальнейшей передачи разработчику/архитектору, если потребуется перенос на отдельный хостинг, добавление бэкенда или новых функций.

## 12. Критерии приёмки

- [ ] Приложение открывается по ссылке без установки и регистрации.
- [ ] Все 3 дня сплита доступны и содержат актуальные данные пользователя.
- [ ] Каждое упражнение имеет иконку, отличимую от иконок других упражнений в том же дне.
- [ ] Отметка выполнения и сброс работают и сохраняются между сессиями на одном устройстве.
- [ ] Интерфейс корректно отображается на экране шириной от 360px.
- [ ] Приложение читаемо как в светлой, так и в тёмной теме.
- [ ] Ссылку можно переслать другому человеку, и у него приложение открывается в рабочем состоянии.

## 13. Открытые вопросы

1. Нужна ли в следующей итерации синхронизация прогресса между несколькими устройствами одного пользователя?
2. Нужен ли товарищам по залу свой набор данных (веса отличаются от автора), или им достаточно скопировать структуру и вписать свои цифры вручную?
3. Стоит ли добавлять таймер отдыха как отдельную задачу следующего спринта?
